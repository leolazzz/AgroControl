# AgroControl

Android-приложение и локальный backend для контроля параметров теплицы, управления контроллером HotBed, анализа фотографий растений и формирования рекомендаций с помощью Ollama и RAG.

## Состав проекта

- `backend`: REST API, MQTT, авторизация, ONNX-модель и RAG.
- `frontend`: Android-приложение.
- `emulation`: MQTT-эмулятор контроллера HotBed.
- `model_pipeline`: итоговый ноутбук обучения и результаты модели.
- `release/AgroControl-1.1.apk`: готовый APK.

## Основные возможности

- просмотр телеметрии контроллера;
- управление режимом, тремя реле, измерением EC и pH;
- распознавание состояния растения по фотографии;
- рекомендации по фотографии или показаниям датчиков;
- регистрация и вход пользователя;
- локальная очередь команд и история действий.

## Распознаваемые классы

Модель распознает 39 состояний пяти культур:

- Томат: здоровое растение, бактериальная пятнистость, ранняя и поздняя фитофторозная гниль, листовая плесень, септориоз, вирус желтой курчавости листьев, вирус табачной мозаики, мучнистая роса, листовой минер и белокрылка.
- Огурец: здоровое растение, ложная и обычная мучнистая роса, антракноз, бактериальное увядание, брюшная гниль, питиозная гниль плодов и гуммоз стебля.
- Перец: здоровое растение, бактериальная пятнистость, церкоспорозная пятнистость листьев, курчавость листьев, дефицит питательных веществ и мучнистая роса.
- Баклажан: здоровое растение, поражение насекомыми, пятнистость листьев, вирус мозаики, мелколистность, белая гниль и увядание.
- Клубника: здоровое растение, ожог листьев, дефицит кальция, серая гниль, пятнистость листьев, мучнистая роса листьев и антракнозная гниль плодов.

## Как создаются рекомендации

Backend работает в гибридном режиме:

1. ONNX-модель определяет класс растения по фотографии. Рекомендацию также можно запросить только по показаниям датчиков.
2. RAG выбирает подходящие сведения из `backend/knowledge/agronomy_knowledge.json` с учетом культуры, результата анализа и телеметрии.
3. На основе найденных материалов создается безопасный черновик рекомендации.
4. Ollama переформулирует его в четыре коротких практических пункта на русском языке.
5. Backend проверяет язык, структуру и завершенность ответа. Если Ollama недоступна или ответ не прошел проверку, приложение получает готовую рекомендацию из RAG без ошибки запроса.

Источник `ollama_rag` означает, что ответ сформирован Ollama с использованием RAG. Источники `rag_rules` и `rag_rules_ollama_unavailable` означают, что использован локальный резервный ответ.

## Запуск backend в Windows

Установите Python, Ollama и модель `qwen3.5:0.8b`, затем выполните:

```powershell
cd C:\project
py -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r backend\requirements.txt
Copy-Item backend\.env.example backend\.env
ollama pull qwen3.5:0.8b
cmd.exe /c run_backend.cmd --host 0.0.0.0 --port 5000
```

## Запуск backend в Linux

```bash
cd AgroControl
python3 -m venv .venv
./.venv/bin/python -m pip install -r backend/requirements.txt
cp backend/.env.example backend/.env
ollama pull qwen3.5:0.8b
./.venv/bin/python backend/app.py --host 0.0.0.0 --port 5000
```

Для стандартной службы Ollama в Linux укажите в `backend/.env`:

```ini
OLLAMA_HOST=http://127.0.0.1:11434
```

Для проверки без физического контроллера используйте `MQTT_EMULATION=true`. Для настоящего контроллера установите `MQTT_EMULATION=false` и заполните параметры MQTT-брокера и `MQTT_DEVICE_ID`.

## Реальный контроллер

Контроллер и backend должны быть подключены к одному MQTT-брокеру. Настройки backend находятся в файле `backend/.env`:

```ini
MQTT_ENABLED=true
MQTT_EMULATION=false
MQTT_BROKER_URL=127.0.0.1
MQTT_BROKER_PORT=1883
MQTT_USERNAME=
MQTT_PASSWORD=
MQTT_DEVICE_ID=hotbed1
MQTT_QOS=1
MQTT_STALE_SECONDS=120
```

Если брокер работает на другом компьютере, замените `127.0.0.1` на его IP-адрес. Поля `MQTT_USERNAME` и `MQTT_PASSWORD` заполняются только при включенной авторизации брокера. Значение `MQTT_DEVICE_ID` должно совпадать с идентификатором настроенного контроллера.

Запустите MQTT-брокер, контроллер и затем backend. При успешном подключении в журнале backend появятся:

```text
MQTT connected: True (rc=0)
MQTT discovery: homeassistant/...
Controller mode: REAL MQTT
```

После появления discovery-сообщений и свежей телеметрии контроллер станет доступен в Android-приложении.
